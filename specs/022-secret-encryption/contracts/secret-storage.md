# Contract: 凭证加密存储、掩码回显与故障语义

**Feature**: 022-secret-encryption | **Date**: 2026-09-01 | 原则五：接口即承诺

## 1. 加密承诺

1. **落库即密文**：Provider API key 与通知渠道 config 敏感项（`password`/`passwd`/`secret`/`token`/`api_key`/`apikey`/`access_key`）经任何写入路径（管理台、API、YAML 播种、启动迁移）落库后均为 `enc:v1:` 密文；直接读取数据库文件无法获得凭证明文。
2. **使用即明文**：所有消费方（LLM 调用、连通性测试、通知发送）经注册表读到的是解密后明文——功能行为与加密前一致，上游契约（`ProviderRegistry`/`NotifyChannelRegistry` 接口与 Def 值对象）零改动。
3. **形态固化**：`enc:v1:` 前缀对外固化；未来算法或密钥体系升级以新版本号增量（`enc:v2:`），既有密文继续可读。
4. **边界如实**：webhook 类渠道 `url`（含内嵌 token）不加密不掩码——地址语义，需完整可见可编辑；威胁模型防「数据库文件单独外流」，文件档密钥与库同目录不防整机沦陷（生产用环境变量档）。

## 2. 主密钥承诺

| 场景 | 行为 |
|------|------|
| 未配置任何东西（全新工作区） | 首启自动生成 `{oryxos.root}/master.key`（0600），静默可用——零新增必配项 |
| 设置 `ORYXOS_MASTER_KEY`（Base64 32 字节） | 以环境变量为准，文件档忽略 |
| 环境变量格式非法 | 启动失败，报错说明格式要求（`openssl rand -base64 32` 生成） |
| 库中有密文而密钥缺失/不匹配 | 启动失败，报错含恢复路径（找回原密钥 / 管理台删除重录）；**不静默降级明文、不清空数据** |
| 主密钥值 | 不出现在日志、错误信息、任何接口响应中；`master.key` 在版本库忽略清单内（`.oryxos/` 整体 gitignore） |

## 3. 迁移承诺

- 存量明文在升级后**首次启动内**全部转为密文，日志记录「已加密 N 条凭证」；重复启动/中断续跑幂等（前缀判别），不重复加密、不破坏数据。
- 单条密文损坏只影响该凭证：启动 WARN 定位条目、使用时清晰报错，系统整体与其他凭证不受影响。

## 4. 掩码回显承诺（管理台 / API）

- `GET /api/v1/notify-channels`（列表/详情）：config 敏感项返回 `****` + 末 4 位掩码；任何查询响应不含凭证明文（Provider 侧既有掩码机制不变）。
- 更新语义：敏感项提交「原值掩码」或空 → 保持原值；提交新值 → 生效。掩码确定性且幂等（`mask(mask(v)) == mask(v)`），是未修改判定的基础。
- 交互范式与 Provider 编辑、API Key「创建时看一次」一致。

## 5. 兼容性承诺

- 零 schema 变更、零新配置必填项、零接口签名变更；JSON 响应仅「敏感项值由明文变掩码」一处语义变化（这是特性目标本身，US3）。
- 全新库、无凭证行、mock provider 场景零感知可用。
