# Data Model: 可插拔存储（Pluggable Storage）

**Feature**: 025-pluggable-storage | **Date**: 2026-09-03

**业务表零结构变更**——本刀改的是「表结构怎么管理」，不是表结构本身。新增的唯一表是 Flyway 自建的 `flyway_schema_history`。

## 迁移序列（SQLite 目录 `db/migration/sqlite/`）

| 版本 | 形态 | 内容 | 幂等依据 |
|------|------|------|----------|
| V1__baseline.sql | SQL | 现 schema.sql 原样平移：18 张 `CREATE TABLE IF NOT EXISTS` + 12 索引；`llm_pricing` 与 AuditSchemaUpgrade 的重复 DDL 去重为一份 | IF NOT EXISTS |
| V2（Java） | JavaMigration bean | AuditSchemaUpgrade 平移：llm_calls 补 cost_micros/profile_name、tool_invocations 补 profile_name/blocked_by、三表补 trace_id、profile/trace 索引 | PRAGMA table_info 列检查（照旧） |
| V3（Java） | JavaMigration bean | MemorySchemaUpgrade 平移：memory_entries 补 agent_name + idx_memory_agent | 同上 |
| V4（Java） | JavaMigration bean | ScheduleSchemaUpgrade 平移：三分支状态机（current/pre-retirement/legacy 重建含 UUID 键映射与行数对账）；结构无法识别仍抛异常拒启 | PRAGMA table_info / index_list（照旧） |
| V5（Java） | JavaMigration bean | NotifyChannelSchemaMigration 平移：notify_channels 补 config 列 | 同上 |

- V1~V5 对任意状态的存量库与全新空库收敛到同一最终结构（现状语义平移）；`baseline-on-migrate=true` + `baseline-version=0` 下存量库不跳过任何版本
- Java migration 仅在 SQLite url 下注册为 bean（PG 无存量库）；checksum 返回固定值保证 history 稳定
- **V6 起新迁移写非幂等干净 SQL**，两 vendor 目录同版本号各一份（history 保证恰好一次）

## PG 目录（`db/migration/postgresql/`）

仅 `V1__baseline.sql`：完整最终结构（= SQLite V1~V5 收敛后的等价结构，含全部后加列与索引），按转写规则：

| SQLite 形态 | 处数 | PG 转写 |
|-------------|------|---------|
| `INTEGER PRIMARY KEY AUTOINCREMENT` | 14 | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| `BOOLEAN NOT NULL DEFAULT 1` / `0` | 7 | `DEFAULT TRUE` / `FALSE` |
| `BLOB`（memory_vectors.embedding / knowledge_chunks.embedding） | 2 | `BYTEA`（VectorCodec float32 小端序字节两库同载荷） |
| `REAL`（llm_pricing 两价格列） | 2 | `DOUBLE PRECISION` |
| TEXT / VARCHAR / TIMESTAMP / UNIQUE / 索引 | 其余 | 原样 |

密文列（providers.api_key、notify_channels.config，`enc:v1:` 前缀）均 TEXT，零转写。

## 配置面（部署契约）

```yaml
# 默认档（零配置）——jar 内置，现状不动
spring:
  datasource:
    url: jdbc:sqlite:oryxos.db
    hikari.data-source-properties: { journal_mode: WAL, busy_timeout: 5000 }
  flyway:
    locations: classpath:db/migration/{vendor}
    baseline-on-migrate: true
    baseline-version: 0

# PG 档（config/application.yml 外部覆盖，模板给示例）
spring:
  datasource:
    url: jdbc:postgresql://db.example.com:5432/oryxos
    username: oryxos
    password: ${ORYXOS_DB_PASSWORD}   # 环境变量注入，不明文
```

`DataSourceVendorPostProcessor`（EnvironmentPostProcessor，spring.factories 注册）：url 为 `jdbc:postgresql:` 前缀时清除 SQLite 专属默认（两个 PRAGMA 型 hikari 属性 + `database-platform=SQLiteDialect`），driver 由 Boot 按 url 自动推导；url 为 sqlite/缺省时零动作。

## 启动序（收敛后）

```
DataSource → Flyway（{vendor} 目录，PG 下内建锁保证多副本恰好一次）
  → JPA EntityManagerFactory（ddl-auto=none 不变）
  → SecretMigration Bean（@DependsOn flyway；密钥守卫拒启 + 存量加密，逻辑不变，
      「config 列未就绪」容错删除——V5 已保证列存在）
  → providerRegistry / notifyChannelRegistry 播种（形参依赖 SecretMigration，现状纪律）
```

被拆除的现状：`spring.sql.init` 执行 schema.sql、4 个升级 Bean 散落在业务 Bean 方法体、1 个 CommandLineRunner 跑在 refresh 之后。
