# Feature Specification: 高可用共享工作区与可插拔文件存储

**Feature Branch**: `042-workspace-storage`
**Created**: 2026-09-17
**Status**: Implemented and locally verified; T013 external shared-storage acceptance pending
**Input**: 复用 027，补齐共享工作区可靠性，文件读写标准接口插件化；首期 POSIX/NFS/云 NAS，后续可扩展其他存储。

## User Scenarios & Testing

### User Story 1 - 配置可替换的外部文件存储 (Priority: P1)
运维为所有实例选择同一个外部工作区；开发者提供存储插件即可更换后端，业务 Agent、Skill、知识和输出不绑定某个厂商。
**Why this priority**: 消除应用节点对文件资产的独占，同时防止只有接口没有真实调用的空壳插件化。
**Independent Test**: 以可观察的替代插件完成文件读取、写入、列举和删除；错误插件与缺失能力明确拒绝。
**Acceptance Scenarios**:
1. Given 默认单机配置，When 启动与管理文件，Then 保持现有目录和技能绑定语义。
2. Given 外部共享工作区，When 另一节点接管，Then 可读既有 Agent、Skill、知识源与已完成输出。
3. Given 插件缺少所需能力、未知 ID 或重复注册，When 启动，Then 清晰拒绝，不回退本地存储。

### User Story 2 - 故障后自动收敛，避免静默丢失 (Priority: P1)
文件发布中断、数据库通知失败或实例退出后，其他实例能发现已提交内容；未完成内容不当作完整发布。
**Why this priority**: 外置文件系统不能自行解决发布和通知之间的窗口。
**Independent Test**: 故障注入验证自动对账、原子文件写、同名冲突、恢复后的内容一致性。
**Acceptance Scenarios**:
1. Given 发布后版本通知失败，When 服务恢复，Then 不依赖下一次人工编辑即可重载。
2. Given 两个客户端基于相同版本修改同一资产，When 提交，Then 不允许静默覆盖，失败者得到明确冲突。
3. Given 文件写入中断，When 其他实例读取，Then 读到旧完整或新完整文件；多文件发布可恢复且不能被误报为目录事务。

### User Story 3 - 存储身份与故障可观测 (Priority: P1)
共享存储断开或挂载到错误位置时，运维看到不就绪，系统不在本机生成替代目录。
**Independent Test**: 删除或替换工作区身份标记后读写失败、readiness 失败；恢复正确挂载后可重试。
**Acceptance Scenarios**:
1. Given 配置共享模式，When 挂载为空或身份不同，Then 启动拒绝且不创建业务文件。
2. Given 运行中的共享存储不可用，When 写入请求到达，Then 不报告成功；恢复后可继续。

### User Story 4 - 输出可追溯与部署可恢复 (Priority: P2)
不同 Agent/执行的产物隔离；已发布产物可在任一实例读取。工作区支持保留软链接的迁移与校验，并可从备份恢复。
**Independent Test**: 两次执行生成同名输出而互不覆盖；迁移到另一共享路径后比对文件摘要和链接目标。

### Edge Cases
- 共享身份标记证明配置一致，不证明物理存储高可用；必须另做跨节点验收。
- 存储挂载阻塞可能阻塞内核 I/O，应用超时不等于取消内核请求；探测须隔离并限制并发。
- 恢复后旧写者不能覆盖已接受的新版本；并发控制不能只依赖进程内 synchronized。
- Shell 和第三方解析器需要本地路径；插件必须声明或提供执行视图，不能绕过沙箱。
- 本地缓存与 staging 可丢失，但不得成为已发布资产的唯一副本。

## Requirements

### Functional Requirements
- **FR-001** 文件读写、列举、属性、删除、移动通过统一标准存储接口；选择插件后核心调用不得另建默认本地后端。
- **FR-002** 显式配置后端 ID，支持外部扩展；未知/重复 ID、缺失能力拒绝启动。首期提供本地和共享文件系统。
- **FR-003** 保留 Agent 目录、真实路径边界及受控相对软链接；后端无法支持时明确拒绝，不模拟为成功。
- **FR-004** 共享模式必须校验运维预置的工作区身份，不自动初始化未知挂载；读写故障不回退本地。
- **FR-005** 复用 027 的共享版本总线，并补充自动对账以恢复遗漏通知。
- **FR-006** 管理写入提供版本冲突检查与可恢复提交；规范文件读取配对工作区代次，所有第一方资产编辑器回传读取时的 If-Match。预约前拒绝不改变代次；处理器返回 4xx 保守推进代次并归档未知副作用，5xx 保留阻塞预约（详见契约状态表）。准确区分单文件原子性和多文件事务语义。
- **FR-007** 受管理的文件覆盖和下载完成前不暴露部分内容，异常清理暂存内容。
- **FR-008** 输出按 Agent 与执行标识隔离，Shell 产物经明确发布边界进入可见工作区。
- **FR-009** 工作区健康影响 readiness，提供可观察的身份、后端、故障与重载状态；不泄露凭证。
- **FR-010** Helm 支持接入已有共享卷；提供 NFS 部署、迁移、恢复与跨节点验收步骤。
- **FR-011** 不实现 OSS/S3 原生插件、不购买云资源；提供可扩展契约及能力拒绝测试，不能宣称已支持对象存储。
- **FR-012** 自动化覆盖插件替换、路径安全、故障恢复、冲突、输出隔离；真实共享存储验证单列，不以同机测试替代。

### Key Entities
- 工作区：稳定身份、后端类型、能力和健康状态。
- 文件资产：逻辑路径、种类和内容；管理发布代次是工作区范围的不透明 UUID（初值 initial），与 SHA-256 内容/备份摘要分开。
- 发布：暂存内容、预期修订、提交结果与恢复状态。
- 执行产物：Agent、执行标识、相对路径和完成状态。

## Success Criteria
- **SC-001** 替换合规插件无需修改 Agent/Skill 业务规则，测试证明请求经过所选实现。
- **SC-002** 正常跨副本变更延续 027 的 3 秒目标（默认 1s 轮询，从 A 发布成功到 B 运行注册表可见，测量方法见 quickstart）；漏通知在配置的对账周期加一次重载耗时内自动发现。
- **SC-003** 错误共享挂载不能产生成功写入；客户端能区分冲突与存储不可用。
- **SC-004** 单文件读不到半写结果；并发修改和恢复测试无静默内容覆盖。
- **SC-005** 两次执行的同名输出不相互覆盖，完整输出在任一副本可读。
- **SC-006** 故障转移与备份恢复检查验证文件摘要、软链接和内容完整性；真实跨节点验收证据单列。

## Assumptions / Clarifications
- 用户已批准首期开发和存储抽象；无需再次审批例行实现选择。
- 先采用挂载型高可用文件系统，运维负责提供具备冗余的 NFS/云 NAS/CephFS；应用不自建生产存储集群。
- 027 的同名后写覆盖策略由本特性管理写入冲突语义取代；原始外部直接改盘不具备事务承诺。
- 保留现有路径与软链接契约；对象存储未来通过能力与受控执行视图扩展。
- 现有 Docker 数据和运行实例不用于破坏性故障注入；验证使用独立目录、实例和数据库。
