# Quickstart / acceptance

1. 使用隔离临时目录完成自动测试，运行 `mvn -pl oryxos-boot -am test`（质量门禁按项目配置）。
2. 管理员挂载 RWX NFS/NAS，在根预置 `.workspace-id`，所有实例配置相同身份、shared-posix provider 和 PostgreSQL。
3. 两个独立节点启动，A 创建/更新 Agent、Skill、知识源，B 验证内容及相对链接；模拟漏版本通知，等待对账周期再次检查。
4. 断开/错挂共享卷，验证实例不就绪且拒绝新写入，没有创建新的本地工作区。
5. 并发提交相同旧版本，确认一个成功另一个冲突；注入中断，停写后按提交日志恢复并核对摘要。
6. 两个 Agent/两次运行输出同名文件，确认路径分离；失败下载不暴露部分文件。
7. 停所有写者，保留软链接迁移备份并核验 hash；新节点恢复，移除旧节点后读取同样内容。

真实跨主机共享卷验收需要部署环境，单机临时目录测试不计为通过该项。


## SC-002 收敛时间测量

使用两个独立节点、默认 `workspace-poll-interval=1s`，记录明确的对账周期。每次以 A 管理发布成功响应为起点，轮询 B 的运行注册表所服务的行为/配置直到观察到该次唯一标记为终点；不能用直接读取规范文件的编辑 GET 代替运行注册表收敛。连续 20 次创建/更新/删除，保存每次时间差及最大值，正常通知每次目标 ≤3s；记录网络采样间隔及测量误差。

遗漏通知场景在隔离验收卷发布文件后刻意跳过版本 bump，并保证刚完成上一轮对账；以文件完整发布为起点，验证 B 在一个配置对账周期加一次重载耗时内生效。记录重载耗时，不把大文件解析时间记为零。真实共享环境结果填入 acceptance.md；确定性时钟单元测试只能证明调度逻辑。
