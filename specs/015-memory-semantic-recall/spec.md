## 1. 背景与目标

### 为什么做

Agent 的长期记忆目前只能「按字面找回」：`recall_memory` 在归档区做简单关键词匹配。用户上周说
「发布流程在灰度环节踩了雷」，这周问「上次那个部署的坑后来怎么处理的」——没有一个共同关键词，
记忆找不回来。这是核心阶段的**刻意克制**（记忆行为契约四：「recall 是关键词检索不做复杂化」），
路线图方向 B 约定：知识检索基建就位后升级记忆检索。014 已交付这套基建并按「不带 knowledge
语义」的形状设计（FR-016），现在到了兑现的时刻。

### 这个特性是什么（一句话）

让 `recall_memory` 从「字面匹配」升级为「语义 + 关键词双路检索」——Agent 能按**意思**找回归档
记忆；向量化服务不可用时自动降级为现状行为；**未配置向量化的部署行为与今天完全一致**，零配置、
零破坏。

### 做成了长什么样（三个画面）

1. 用户问 Agent「我上次说的那个部署问题后来怎么解决的」，记忆里写的是「发布流程在灰度环节踩雷，
   回滚后改为分批放量」——措辞完全不同，语义召回命中，Agent 答上来了；
2. 管理员什么都不用配：已为知识库配了向量化的部署，记忆检索自动同享同一配置；没配的部署，
   一切照旧；
3. 升级后首次启动，存量的历史记忆被自动补建索引，30 秒后旧记忆也能按语义找回。

## 2. 术语表

| 术语           | 定义                                                                       |
| ------------ | ------------------------------------------------------------------------ |
| **核心区 / 归档区** | 长期记忆的两个分区（既有概念）：核心区全量注入每轮 prompt、永不截断；归档区容量大、注入截断、检索找回。**检索（含本特性）只作用于归档区**。 |
| **记忆条目**      | `save_memory` 写入的一条记录（既有概念）。本特性中一条记忆 = 一个向量，不切分。                         |
| **双路召回 / 融合** | 与知识检索同款：语义（向量）与关键词两路并行找候选，按名次融合排序（014 术语表同义）。                            |
| **降级**        | 向量化不可用时检索退回纯关键词路（即升级前的现状行为）。                                             |
| **记忆向量索引**    | 归档区条目的向量副本，派生数据——删掉可从记忆本体全量重建，不是第二份记忆。                                   |

**需求用语约定**：MUST = 必须满足；MUST NOT = 必须禁止。FR/US/SC 编号为稳定标识符。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 终端用户：按意思找回记忆（Priority: P1）

用户与 Agent 的历史交流沉淀在归档记忆里。此后用不同措辞提起旧事，Agent 通过语义召回找回相关
记忆；涉及精确代号/工单号/专名时，关键词路保证不丢。用户感知到的只是「这个 Agent 记性变好了」。

**Independent Test**: 手工写入若干归档记忆（含语义相近措辞不同、含精确代号两类），经
`recall_memory` 验证两路召回与融合。

**Acceptance Scenarios**:

1. **Given** 归档区有「发布流程在灰度环节踩雷，回滚后改为分批放量」，**When** 检索「上次部署出的问题怎么解决的」，**Then** 该条目被召回（语义路，无共同关键词）。
2. **Given** 归档区有含工单号「OPS-4721」的条目，**When** 检索「OPS-4721」，**Then** 该条目被召回（关键词路，精确匹配不劣于现状）。
3. **Given** 检索与任何记忆无关的内容，**Then** 返回「没有找到相关记忆」，不编造。
4. **Given** 任意一次 `recall_memory` 调用，**Then** 照旧进入工具审计，且埋点含命中明细与降级标记。
5. **Given** 两个 Agent 各有自己的记忆，**When** 任一 Agent 检索，**Then** 只命中自己的记忆，绝不跨 Agent。

---

### User Story 2 - Agent 作者/管理员：零配置升级、完全向后兼容（Priority: P1）

已有部署升级到本版本后：配了向量化（知识库同一份配置）的，记忆检索自动变聪明、存量记忆自动补
索引；没配的，`recall_memory` 行为与升级前逐字节一致——不报错、不变慢、不要求任何迁移动作。

**Acceptance Scenarios**:

1. **Given** 未配置向量化的部署，**When** 升级后调用 `recall_memory`，**Then** 结果与升级前完全一致（CI 可断言）。
2. **Given** 已配置向量化、存量有 N 条归档记忆的工作区，**When** 服务启动，**Then** 30 秒内存量条目全部可被语义检索（对账补索引）。
3. **Given** 向量化模型/维度变更，**When** 服务启动，**Then** 记忆索引被自动重建，不出现新旧向量混比（记忆量小，无需知识库式的手动重建入口）。
4. **Given** 向量化服务故障期间，**When** Agent 调 `save_memory`，**Then** 记忆 100% 落库成功（仅标记待索引，恢复后对账补齐）；同期 `recall_memory` 自动降级关键词并标注。

---

### User Story 3 - 集成开发者/CI：无 key 环境确定性验证（Priority: P2）

mock provider 提供确定性向量（014 同款），CI 无凭证走通「写入 → 索引 → 双路检索 → 降级」全链路
且结果可重复断言。

**Acceptance Scenarios**:

1. **Given** 仅 mock provider 的环境，**When** 走通写入与检索全流程，**Then** 相同输入恒得相同结果。

---

### Edge Cases

- **一致性**：记忆写入与向量化的一致性取舍与知识**相反**——知识导入可显式失败（源文件还在，可重试）；记忆写入是对话的副作用，丢了就永远丢了 → 条目落库永远优先，索引异步补齐（FR-004）。
- **降级中途发生**：单次检索过程中向量化超时/报错 → 该次退回纯关键词结果并标注，对话不中断。
- **超长条目**：超过向量化输入上限的条目截断后向量化（检索召回的仍是完整条目原文）。
- **空归档区**：检索返回「没有找到相关记忆」（现状行为不变）。
- **后端切换**：`memory.backend` 在 markdown/sqlite 间切换后，索引对账以当前后端的条目为准重建；mem0 档不产生本地索引。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `recall_memory` MUST 升级为双路召回（语义 + 关键词并行）+ 名次融合，检索范围仍限归档区；工具名、参数、返回形态 MUST 保持不变（对模型与既有 Agent 完全向后兼容）。
- **FR-002**: 语义能力 MUST 复用 014 检索基建（向量化端口、融合流水线、向量存储档位），MUST NOT 新建 embedding 凭证体系；向量化配置升格为全局 `embedding.*` 段（知识与记忆共用同一份），`knowledge.embedding.*` MUST 作为兼容别名继续生效（Clarify-Q1）；未配置 = 纯关键词模式。
- **FR-003**: 记忆向量索引 MUST 为派生数据：可随时从记忆本体全量重建；删除索引 MUST NOT 影响记忆本体与核心区注入。
- **FR-004**: `save_memory` MUST 先落记忆本体再异步向量化；向量化失败 MUST NOT 使写入失败或丢条目（标记待索引，随对账补齐）。
- **FR-005**: 服务启动 MUST 对账归档区条目与向量索引：补齐缺失、清理孤儿；向量模型/维度与当前配置不一致时 MUST 自动重建记忆索引，MUST NOT 混比新旧向量。
- **FR-006**: 向量化不可用时检索 MUST 自动降级纯关键词（即升级前行为）并在结果中标注；恢复后无需干预自动回到双路。
- **FR-007**: 索引与检索 MUST 按当前 Agent 圈定作用域，MUST NOT 跨 Agent 命中；markdown 与 sqlite 后端档 MUST 行为一致，mem0 档 MUST 直通其自身检索、不建本地向量索引。
- **FR-008**: mock provider MUST 提供确定性向量使全链路可在 CI 稳定断言（复用 014 mock）。
- **FR-009**: `recall_memory` 调用 MUST 照旧入工具审计；埋点结构 MUST 对齐知识检索的形态（查询原文 + 命中明细 + 降级标记 + 耗时），供未来统一观测直接消费。
- **FR-010**: 记忆行为契约修订：契约四由「recall 只做简单关键词」修订为「recall 双路可降级，降级态即原关键词行为」；契约一（不缓存）、二（核心区不截断）、三（scope 显式）MUST 保持不变。
- **FR-011**: sqlite 后端档的记忆条目 MUST 补齐 Agent 维度（既有作用域缺口随本特性修复，Clarify-Q2）：新写入按当前 Agent 落维度；存量无主行归属全局占位、随迁移说明可读呈现；修复后 sqlite 档与 markdown 档的 per-Agent 语义一致。
- **FR-012**: `save_memory` 工具的分区参数说明 MUST 讲清两区语义与取舍依据（core = 少量常驻事实，每轮都在上下文；archival = 一般值得记的事件，需要时检索找回；不确定填 archival），帮助模型正确分区；工具名与参数结构 MUST 保持不变（仅描述文案增强）。

### Key Entities

- **记忆向量索引条目**: 归档记忆条目的向量副本；属性：条目标识、所属 Agent、向量、向量模型标识与维度、索引状态（待索引/已索引）。派生数据，可全量重建。

## Success Criteria *(mandatory)*

- **SC-001**: 语义找回：人工构造 10 组「措辞不同、语义相近」的记忆-查询对，语义路召回 ≥ 8 组（人工评审软指标，用真实向量化模型评审，不阻塞其余验收）。
- **SC-002**: 向后兼容：未配置向量化的部署，升级前后 `recall_memory` 对同一输入的返回完全一致（CI 断言）。
- **SC-003**: 精确匹配不回退：含精确代号/专名的查询，召回不劣于升级前纯关键词行为（关键词路保底，CI 断言）。
- **SC-004**: mock 环境全链路确定可重复（CI 稳定断言）。
- **SC-005**: 存量补索引：既有归档记忆的工作区启动后 30 秒内全部可被语义检索。
- **SC-006**: 写入零丢失：向量化故障期间 `save_memory` 100% 落库成功。
- **SC-007**: 万条归档条目规模下单次检索 1 秒内返回（与 014 同规模假设）。

## Assumptions

- **规模假设**：单 Agent 归档记忆万条以内；超出后与知识库同承接路径（可插拔存储换档）。
- **条目不切分**：一条记忆 = 一个向量；超长条目截断向量化、召回返回完整原文。
- **配置复用**：向量化 provider/model 走全局 `embedding.*` 段（旧键兼容）；配置缺失时本特性静默处于纯关键词模式（不告警刷屏，审计埋点可查降级态）。
- **宪法遵从**：同步执行 + 虚拟线程；审计照旧；无新凭证；存储变更走手工 DDL（若涉及）。
