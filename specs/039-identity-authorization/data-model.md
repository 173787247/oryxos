# Data Model: 企业身份与授权基座（Identity & Authorization）

**Feature**: 039-identity-authorization | **Date**: 2026-09-14

**业务表零重设计**——本刀改的是「谁能不能碰这些表/资源」，不是表结构本身：**唯一的结构变更是 `web_users` 加一列 `roles`，唯一的新表是授权拒绝记录 `authz_events`**。`web_sessions`、`api_keys`、`sessions`、`tool_policy_rules` 与两张审计表的列与语义零改动（宪法五、宪法八各一条硬口径）。

## web_users（加列）

> **阶段二**：本阶段工作树尚未建该列（角色由 `oryxos.web.rbac.roles.*` 过渡提供）；本列是目标形态，落库后配置默认档收紧为空。

| 列 | 类型 | 约束 | 说明 |
|----|------|------|------|
| `roles` | VARCHAR(255) | NOT NULL DEFAULT `'VIEWER'` | 角色唯一权威源；逗号分隔的**规范化**角色名集合（大写、去重、按 `VIEWER,EDITOR,ADMIN` 顺序输出）；存量账号升级后即只读档 |

### 字段约束

- 取值只允许 `VIEWER` / `EDITOR` / `ADMIN`（`io.oryxos.core.auth.Role` 的三个枚举名）；未知 token 由 `WebUserService.rolesOf` 记 WARN 后**忽略**（降权，绝不向上兜底成高权限，FR-008）。
- 空串或解析结果为空 = 该主体不授权（拒绝），不是「默认给个档」。
- 写入只经 `WebUserService.setRoles(...)`（`oryxos user role` CLI 的落点），不做「首个账号自动 ADMIN」这类隐式提权。
- 不设唯一约束、不建外键（与 `web_sessions.username` 同口径：单列字符串，账号删除后行仍按 012 语义存活到过期，但角色解析结果为空即不授权）。

### 生命周期

```
存量账号（升级即 VIEWER） --oryxos user role <name> <ROLE>--> 新档位（下一次请求即生效，无缓存）
```

- 会话本身不受影响：012 的「session 有效即通过认证、不查 `web_users.enabled`」不变（`WebSessionService.findValid`）；**但角色每请求从本列重解析**，因此撤权/降权在下一个请求即生效，不存在 12 小时延迟窗口。

## authz_events（新表）

> **阶段二**：本阶段工作树的拒绝留痕是结构化 WARN 日志；本表是落库目标形态（V8 创建），落地后 SC-003 才可判。

授权拒绝记录。**只写拒绝行**——放行不落库（避免每请求一次写放大，FR-007）。

| 列 | 类型（SQLite / PG） | 约束 | 说明 |
|----|---------------------|------|------|
| `id` | INTEGER AUTOINCREMENT / BIGINT IDENTITY | PK | 主键 |
| `principal_kind` | VARCHAR(16) | NOT NULL | `USER` / `API_KEY` / `ANONYMOUS` |
| `principal_id` | VARCHAR(128) | NOT NULL | 用户名 / Key **名称** / `anonymous`；绝不含 Key 明文 |
| `action` | VARCHAR(32) | NOT NULL | `Action` 枚举名 |
| `resource_type` | VARCHAR(32) | 可空 | `ResourceRef.type` |
| `resource_id` | VARCHAR(255) | 可空 | `ResourceRef.id`（整体性动作为空） |
| `reason` | VARCHAR(512) | NOT NULL | 决策点给出的可读理由（`Decision.reason`） |
| `request_method` | VARCHAR(16) | 可空 | HTTP 方法 |
| `request_path` | VARCHAR(512) | 可空 | 请求路径（用于定位映射表命中项） |
| `trace_id` | VARCHAR(64) | 可空 | MDC 中存在 `TraceContext` 时带上，与既有审计表同值语义（021） |
| `created_at` | TIMESTAMP / TIMESTAMPTZ | NOT NULL | 拒绝时刻 |

索引：`idx_authz_events_created_at (created_at)`、`idx_authz_events_principal (principal_id, created_at)`（按主体盘点「谁老被拦」）。

### 字段约束

- 无更新、无删除路径（追加型审计，`AuthzEventRepository` 不提供 `delete*` 方法）。
- 写失败（库不可写）只记 ERROR 日志，**不改变裁决**：拒绝照旧返回 403，不得因审计失败放行。
- 不存请求体、不存 Header、不存凭证片段。

## Java 侧映射（oryxos-storage）

| 类 | 职责 |
|----|------|
| `WebUser`（`@Entity`，既有，修改） | 加 `roles` 字段映射；不引入 `RolesConverter` 之外的新依赖（解析/序列化收在 Service 层） |
| `WebUserService`（既有，修改） | `rolesOf(String username)`：每请求解析（未知 token WARN 降权、账号不存在/禁用返回空集）；`setRoles(String username, Set<Role> roles)`：规范化后写库；供 `BasicAuthFilter`、`ApiKeyAuthFilter`（session 分支）、`AuthApiController./me` 与 CLI 共用 |
| `AuthzEvent`（`@Entity`，新增） | `authz_events` 表映射，字段同上；镜像 `ToolInvocation` 的注解与 `SuppressFBWarnings` 风格 |
| `AuthzEventRepository`（新增） | 追加写 + 按主体/动作/时间查询（`findByPrincipalIdOrderByCreatedAtDesc`、`findByActionOrderByCreatedAtDesc`、`findAllByOrderByCreatedAtDesc`）；**不提供删除** |
| `AuthzEventRecorder`（新增） | `record(Principal, Action, ResourceRef, String reason, HttpServletRequest)`：装配实体、截断超长文本、落库；任何异常只记 ERROR 不抛出（FR-007） |

## 派生视图（不落库）

- **`AuthorizationService.Decision`**：一次裁决的结果 `{allowed, reason}`，内存对象；被两扇 Filter、拒绝响应与管理台「为什么」共用同一文案。
- **`Principal`**：请求级不可变值，不是持久化实体；`roles` 由 `web_users.roles` 解析而来（API Key 主体来自配置默认档）。
- **角色矩阵**：`RoleBasedAuthorizationServiceImpl` 内的静态集合（代码常量，评审可通读），`matrix()` 只读视图供管理台/文档展示，不落库。

## 配置面

```yaml
oryxos:
  web:
    rbac:
      enabled: false                     # 默认关：行为与引入授权层之前逐字节一致（FR-005）
      deny-anonymous: true               # 授权启用时匿名主体默认拒绝（安全默认值）
      roles:                             # 前缀独立（oryxos.web.rbac.roles）：与 rbac.* 同前缀会在启动时绑定冲突
        default-user-roles: [ADMIN]      # 过渡入口：角色尚未落库时管理台账号的默认档（防单机部署自锁）
        default-api-key-roles: []        # 默认空 = 机器凭证不默认授权（要放行需显式授予，如 [EDITOR]）
```

- 全部键**默认值即现状语义**：不配置时 `enabled=false`，其余键不参与任何判定。
- `default-user-roles` 默认 `ADMIN` 是**过渡值**：角色落库（`web_users.roles`）落地后，主体总是自带角色、该键不再兜底，应显式收紧为空（解析不到角色即拒绝），并由启动期「无 ADMIN 账号即拒启」兜住锁死风险——两条要一起做，缺一就会在「锁死」与「人人 ADMIN」之间二选一。
- `default-api-key-roles` 默认空：API Key 无库内归属（018 留到 v1.0 租户模型），机器凭证不默认授权；显式授予后仍受 Key 能力上限约束（不减 `MANAGE_MEMBERS` / `MANAGE_POLICIES`）。
- 「认证开 → 授权才有对象」：`rbac.enabled=true` 而 `web.apikey.enabled=false` 时，没有门会产出主体，本刀按 FR-012 **拒绝启动**并指路，不让授权层静默失效。

## 不新增的

- 不加 `web_user_roles` / `web_roles` 关联表（三档 + 一用户一档是主流形态；`Principal.roles` 已是集合，将来扩多角色只需改存储、不动接口）。
- 不加 `api_keys.owner` / `scope` / `expires_at`（018 已裁决留到 v1.0 租户模型）。
- 不加 `sessions` 归属相关列（会话所有权不在本刀，控制台尚未写真实 `user_id`）。
- 不加认证事件表（`auth_events` 归 #461）；`authz_events` 不承载登录/登出/Key 使用事件。
- 不改 `tool_invocations` / `llm_calls` 任何列（本刀拒绝不进这两张表，见 research R7）。
- 不改 `.oryxos/` 工作区任何文件形态：无 `TODO`/策略文件落盘，角色全部在库。
