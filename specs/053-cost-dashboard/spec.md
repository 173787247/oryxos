# Feature Specification: 成本看板（Cost Dashboard）

**Feature Branch**: `053-cost-dashboard`

**Created**: 2026-10-14

**Status**: Draft

**Input**: User description: 管理台新增「成本」页面与菜单，让运维/管理员直观查看 LLM 与工具调用成本（数据来自已有成本账本）。首版含 KPI、维度筛选、按天趋势、成本构成、流水明细；人民币展示；成本功能未开启时显示空状态。不做 Top N 与定价管理。

## Clarifications

### Session 2026-10-14

- Q: 成本页首次打开默认时间窗？ → A: 近 7 天
- Q: 按天聚合用哪个时区的自然日划天？ → A: 服务端本地时区
- Q: 成本流水明细表默认排序？ → A: 时间倒序（最新在上）
- Q: 成本金额（元）展示保留几位小数？ → A: 2 位（初定 4 位，后改为 2 位）
- Q: KPI 的「调用数」和「平均延迟」按什么口径？ → A: 仅统计 LLM 调用（工具调用不计入这两个 KPI）
- Q: 成本趋势折线画几条线？ → A: 单条「每日 LLM 成本」线（工具成本默认为 0，不单列；LLM/工具拆分由构成图负责）
- Q: 日期范围是否设上限？ → A: 设上限约 92 天（单次查询最多跨约 3 个月）
- 备注（事实澄清）：工具成本由管理员按工具配固定单价（`CostProperties.toolCosts`，默认 0），非 token 计费；未配置时工具成本恒为 0。
- Q: 工具成本默认 0，构成图意义不大，工具侧看什么？ → A: 工具侧看「调用次数」并按 agent 归集（取代原 LLM/工具成本构成图）；账本工具条目已含 sourceKind=TOOL、sourceRef=工具名、agentName，数据支持。
- Q: 维度筛选器的可选值怎么给用户？ → A: 枚举类（agent/provider/model/team）用下拉（后端提供去重可选值），ID 类（run/task）用文本输入/粘贴。
- Q: 开启 RBAC 时成本页/接口最低角色？ → A: VIEWER（只读）；新增 cost 查询接口须在 RequestActionResolver 登记为读动作（fail-closed，不登记即 403）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理员总览成本（Priority: P1）

管理员打开管理台「成本」页，一眼看到当前关注范围内的成本总览：总成本、LLM 成本、工具成本、消耗 token、调用次数、平均延迟。无需查库或翻日志。

**Why this priority**: 这是看板的核心价值——把分散在账本里的成本变成一屏可读的总览。缺了它整个页面没有意义。

**Independent Test**: 在有成本数据的环境打开该页，KPI 卡片显示非空、数值与账本汇总一致即通过。

**Acceptance Scenarios**:

1. **Given** 账本中已有成本记录，**When** 管理员打开成本页，**Then** 顶部 KPI 卡片展示总成本、LLM 成本、工具成本、总 token、调用数、平均延迟，成本以人民币（元）显示。
2. **Given** 账本中暂无任何成本记录，**When** 打开成本页，**Then** KPI 显示为零值而非报错或空白。

---

### User Story 2 - 按维度下钻（Priority: P1）

管理员按 agent / team / provider / model / run / task 任一或组合维度过滤，KPI、图表、明细随之刷新，定位"哪个 Agent / 哪个模型最费钱"。

**Why this priority**: 总览之外，归因是成本治理的第一诉求；与总览同等重要。

**Independent Test**: 选择某个 agent 过滤后，页面所有区块只反映该 agent 的成本，且与按该维度查账本结果一致。

**Acceptance Scenarios**:

1. **Given** 多个 agent 都有成本，**When** 选择某一 agent 过滤，**Then** KPI、趋势、构成、明细均只统计该 agent。
2. **Given** 组合选择 provider + model，**When** 应用过滤，**Then** 结果为两条件同时满足的成本。
3. **Given** 清空所有过滤，**When** 刷新，**Then** 回到全量范围。

---

### User Story 3 - 看成本随时间变化（Priority: P2）

管理员选择一个日期范围，查看按天的成本趋势折线，判断成本是平稳、上涨还是某天异常。

**Why this priority**: 趋势是发现异常、做预算判断的关键，但在总览+归因可用后才有增量价值，故 P2。

**Independent Test**: 选定日期范围后，折线图按天给出成本点，点数与范围内的天数一致，数值随过滤维度联动。

**Acceptance Scenarios**:

1. **Given** 选定起止日期，**When** 查看趋势，**Then** 折线按天展示该范围内每日成本。
2. **Given** 同时设置了维度过滤，**When** 查看趋势，**Then** 趋势只反映该维度的每日成本。
3. **Given** 某天无成本，**When** 查看趋势，**Then** 该天显示为零而非断点或缺失。

---

### User Story 4 - 看工具调用分布（Priority: P2）

管理员查看当前范围内的工具调用情况——按 agent 看哪个 Agent 触发了多少次工具调用（可再按工具名细分），理解工具使用的热点。因工具成本默认为 0，此处以调用次数而非成本为口径。

**Why this priority**: 工具侧没有有意义的成本，但"谁在频繁调工具、调了哪些工具"对使用画像与排查有价值，锦上添花，P2。

**Independent Test**: 工具调用面板按 agent 展示工具调用次数，随过滤与日期范围联动，次数与账本中 `sourceKind=TOOL` 的条目统计一致。

**Acceptance Scenarios**:

1. **Given** 多个 agent 触发过工具调用，**When** 查看工具调用面板，**Then** 按 agent 展示各自的工具调用次数。
2. **Given** 选择了某工具名细分，**When** 查看，**Then** 展示该工具被各 agent 调用的次数。
3. **Given** 当前范围无工具调用，**When** 查看，**Then** 显示空态而非报错。

---

### User Story 5 - 查成本流水明细（Priority: P2）

管理员查看成本流水明细表（时间、agent、model、token、成本、延迟、traceId），可分页、按列排序，用 traceId 关联到具体一次处理。

**Why this priority**: 明细是从聚合下钻到单条的最后一环，支撑排障与核对。

**Independent Test**: 明细表按当前过滤展示流水，可翻页、可按成本/时间排序，字段齐全。

**Acceptance Scenarios**:

1. **Given** 当前范围有多条流水，**When** 查看明细表，**Then** 每行含时间、agent、model、token、成本（元）、延迟、traceId。
2. **Given** 流水超过一页，**When** 翻页，**Then** 正确加载下一页且过滤条件保持。

---

### Edge Cases

- **成本功能未开启**：当 `oryxos.cost.enabled=false`，成本查询不可用（接口返回不可用）。页面必须显示明确的「成本功能未开启」空状态与开启指引，而非报错白屏或无限加载。
- **空数据**：账本为空或过滤后无结果时，KPI 显示零、图表显示空态、明细表显示「暂无数据」，均不报错。
- **日期范围非法**：起始日期晚于结束日期、或范围过大时，页面给出可读提示而非崩溃。
- **成本精度**：成本由微元换算为元（÷1,000,000）后统一按 2 位小数展示；单条极小额成本可能显示为 0.00（可接受），但聚合值基于原始微元计算故总量准确；明细行 SHOULD 提供原始精确值的查看方式（如悬浮提示）以免误读。
- **延迟/构成为空**：某些流水无延迟或只有单一成本来源时，平均延迟与构成图需正确处理缺失，不出现 NaN/除零。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理台 MUST 在 `/admin` 下提供一个「成本」页面，并在管理台导航中新增对应菜单项可进入。
- **FR-002**: 成本页 MUST 展示 KPI：总成本、LLM 成本、工具成本、总 token、LLM 调用次数、平均延迟、**工具调用次数**；成本以人民币（元）展示。其中「LLM 调用次数」与「平均延迟」MUST 仅统计 LLM 调用；「工具调用次数」MUST 统计账本中 `sourceKind=TOOL` 的条目数（工具成本默认 0，故工具侧以调用次数而非成本为主指标）。
- **FR-003**: 成本页 MUST 支持按 agent / team / provider / model / run / task 维度（单选或组合）过滤，过滤后 KPI、趋势、构成、明细一致联动。
- **FR-004**: 成本页 MUST 支持选择日期范围，并按天展示**单条「每日 LLM 成本」**趋势折线；首次进入默认展示近 7 天；日期范围 MUST 限制在约 92 天以内（防止超大范围拖垮按天聚合）；按天聚合以**服务端本地时区**的自然日为边界；趋势随维度过滤联动；范围内无成本的日期显示为零。
- **FR-005**: 成本页 MUST 展示「工具调用」面板：按 agent 归集工具调用次数（即哪个 agent 触发了多少次工具调用），MAY 再按工具名（`sourceRef`）细分；随维度过滤与日期范围联动。（取代原 LLM/工具成本构成图——因工具成本默认为 0，成本占比无信息量。）
- **FR-006**: 成本页 MUST 展示成本流水明细表，字段含时间、agent、model、token、成本（元）、延迟、traceId，支持分页（默认每页 50）与按列排序，**默认按时间倒序**（最新在上）。
- **FR-007**: 所有成本数值 MUST 由账本的微元统一换算为人民币元展示（元 = 微元 ÷ 1,000,000），不引入汇率换算；展示统一保留 2 位小数。聚合值（KPI、趋势、构成）MUST 基于原始微元求和后再格式化为 2 位，MUST NOT 先对每条四舍五入再求和（避免累积误差）。
- **FR-008**: 当成本功能未开启（成本查询不可用）时，页面 MUST 显示「成本功能未开启」的空状态与开启指引，MUST NOT 报错白屏或无限加载。
- **FR-009**: 空数据、过滤无结果、非法日期范围等情况 MUST 给出可读的零值/空态/提示，MUST NOT 崩溃或显示错误堆栈。
- **FR-010**: 本特性 MUST 为只读查询展示，MUST NOT 修改计费/落账逻辑，MUST NOT 改动审计表或成本账本的写入路径。
- **FR-011**: 后端 MUST 为成本查询补充时间维度能力：支持按日期范围过滤，并提供按天聚合的成本数据以支撑趋势折线（现有归因查询无时间维度）。
- **FR-012**: 本特性 MUST NOT 包含 Top N 排行与定价管理（留二期）。
- **FR-013**: 后端 MUST 为枚举类维度（agent / provider / model / team）提供去重可选值，供筛选器下拉；run / task 维度以文本输入/粘贴方式过滤，不强制提供候选值。
- **FR-014**: 当启用 RBAC 时，成本页及其查询接口 MUST 以 VIEWER 为最低角色（只读可见）；本特性新增的 cost 查询接口 MUST 在 `RequestActionResolver` 的路径→动作映射中登记为读动作，避免 fail-closed 下未登记路径被 403。

### Key Entities *(include if feature involves data)*

- **成本汇总（Cost Summary）**：当前过滤范围内的聚合结果——总成本、LLM 成本、工具成本、token（输入/输出/合计）、调用数、总/平均延迟。单位：成本为元（由微元换算）。
- **每日成本点（Daily Cost Point）**：趋势折线的一个数据点——日期 + 当日 LLM 成本（元）。
- **工具调用归集（Tool Call Breakdown）**：按 agent（可选再按工具名 `sourceRef`）聚合的工具调用次数，口径为账本中 `sourceKind=TOOL` 的条目计数。
- **成本流水（Cost Entry）**：账本中的一条记录视图——时间、agent、team、provider、model、来源类型、token（输入/输出/合计）、LLM 成本、工具成本、延迟、priceVersion、sessionId、traceId。
- **过滤条件（Cost Filter）**：维度（agent/team/provider/model/run/task）+ 日期范围，贯穿 KPI/趋势/构成/明细。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理员打开成本页后，一屏内（无需额外操作）即可读到总成本及 LLM/工具拆分，首屏加载在常规数据量下数秒内完成。
- **SC-002**: 管理员可在不查库、不翻日志的前提下，通过维度过滤定位"最费钱的 agent/model"，并与账本数据 100% 一致。
- **SC-003**: 选定任意日期范围，趋势折线的每日成本之和 100% 等于该范围 KPI 的总成本（口径自洽）。
- **SC-004**: 工具调用面板各 agent 的工具调用次数之和 100% 等于当前范围内 `sourceKind=TOOL` 的账本条目总数。
- **SC-005**: 成本功能未开启时，100% 显示可读空状态，0 白屏/0 错误堆栈外泄。
- **SC-006**: 明细表每行成本、token、延迟、traceId 与账本对应记录逐字段一致。

## Assumptions

- **默认时间窗**：首次进入默认展示「近 7 天」（已定），管理员可调整日期范围。
- **按天聚合时区**：按天聚合采用服务端所在时区的自然日边界（已定）。
- **明细分页/排序**：默认每页 50 条，可翻页；默认按时间倒序，排序至少支持按时间与成本（已定）。
- **金额小数位**：统一 2 位小数（已定）；聚合值按原始微元求和后再格式化，避免逐条取整累积误差。
- **成本单位来源**：账本底层为微元、定价单位为"元/百万 token"，故展示币种恒为人民币元，无需汇率/多币种。
- **权限**：沿用管理台既有的 `/admin` 访问控制；未启用 RBAC 时不单独定义权限；启用 RBAC 时最低角色 VIEWER，且新增 cost 接口须在 `RequestActionResolver` 登记为读动作（见 FR-014）。
- **复用后端**：优先复用既有成本归因查询与账本服务；仅为"时间维度/按天聚合"补充必要的只读查询能力，不新建并行账本。
- **数据量**：面向企业单实例的常规成本数据量设计；超大规模下的聚合性能优化留后续。
